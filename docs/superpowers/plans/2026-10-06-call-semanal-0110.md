**Goal:** Resolver as pendências da call de Ads de 01/10 no CRM (spec
`docs/superpowers/specs/2026-10-06-call-semanal-0110-design.md`) em 7 pacotes paralelos sobre
uma base comum já entregue (P0).

**Architecture:** P0 (migração base) entra primeiro na branch integradora
`feat/call-semanal-0110`. Cada pacote P1–P7 roda num worktree próprio

Integração: merge sequencial P1…P7 na integradora, suíte completa, type-check e build uma vez.

**Tech Stack:** FastAPI + supabase-py (backend/app), Next.js App Router + shadcn/Radix +
vitest (frontend/src), Postgres 17 (Supabase self-hosted), pytest.

## Regras de execução (valem para todo pacote — leia antes de tudo)

   Todo comando pesado (pytest, vitest, tsc, eslint, npm) roda **dentro de**
   `flock /root/crm-wt/_heavy.lock <comando>` — um por vez na máquina inteira.
   **Proibido:** `next build`, `npm ci/install`, suíte completa do backend, `tsc` do projeto
   inteiro. Rode só os arquivos de teste do seu pacote. A integração roda o resto, uma vez.

     -v $PWD:/repo -w /repo/backend -e SUPABASE_URL=https://example.supabase.co \

     "pip install -q -r requirements-dev.txt >/dev/null 2>&1; python -m pytest -q -p no:cacheprovider tests/<seus_arquivos>.py"

   `/srv/Maquinadevendascanastra/frontend/node_modules` (já criado). Rode
   `cd frontend && flock /root/crm-wt/_heavy.lock npx vitest run <arquivos>` e
   `flock /root/crm-wt/_heavy.lock npx eslint <arquivos alterados>`.

   senha `scratch`) com o esquema de produção no banco-modelo `crm_schema` + P0 já aplicável.
   Crie o seu: `docker exec crm-scratch-pg psql -U postgres -c "create database pN template crm_schema;"`,

   `/root/crm-wt/_scratchdb/`, montado em `/seed`) e as suas migrações. Teste de verdade:
   insert/update e confira o efeito.
5. **Banco de produção: somente leitura** (`docker exec -i $(docker ps -q -f name=supabase_db | head -1) psql -U postgres -d postgres -c "select …"`).
   Nenhum INSERT/UPDATE/DELETE/DDL em produção. Scripts com `--aplicar` **não** rodam em
